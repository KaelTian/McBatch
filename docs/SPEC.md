# McBatch 规格 v1.1

> 本文件是项目唯一权威规格。实现和测试都据此编写;
> 歧义由用户裁决, 任何实测结论(尤其是 ⚠️ 条目)由用户回填到本文档。

## 1. 目标
将带 `[McPoint]` 标注的 POCO 对象映射为三菱 MC 协议(3E 帧)批量读写请求,
以**最少的网络往返**完成整对象的读取与写入。

读契约(实现必须遵守):
    T Read<T>(MelsecMcNet client) where T : new()
读语义: 扫描 T 的全部 [McPoint] 属性 → 生成批量请求计划 → 串行执行 →
      结果逐字段写入一个 **new T()** 并返回。
      T 必须有无参构造函数; client 生命周期归调用方, 本方法不 Dispose。

## 2. 数据模型

### 2.1 点位标注
```csharp
public class MixerState
{
    [McPoint("D100")] public short Speed { get; set; }       // D区 1 字
    [McPoint("D102")] public float Temperature { get; set; }  // D区 2 字
    [McPoint("M10")]  public bool  Running { get; set; }      // M区 1 位
}
```

### 2.2 类型映射表
| CLR 类型 | 区域 | 占用 | 说明 |
|---|---|---|---|
| short / ushort | D | 1 字 | |
| int / uint / float | D | 2 字 | 低地址字为低 16 位 |
| bool | M / X / Y | 1 点 | bool 只能映射到 M/X/Y 位区; 标在 D 区: 扫描阶段抛异常(不支持 bool 落字元件) |
| 其他类型 | 任意 | — | 扫描阶段抛 ArgumentException |

### 2.3 区域与寻址
- 区域前缀: `D`(数据寄存器,字) `M`(内部继电器,位) `X`(输入,位) `Y`(输出,位)
- D/M 区域地址按十进制解析
- ⚠️ **已知未知项 #1**: X/Y 区域地址进制(八进制/十六进制/十进制)未钉死。
  三菱 X/Y 为 I/O 编址, 与 D/M 规则不同, 是实现 bug 高发区。
  **处置**: 用 conformance 测试 `A3_Xy_Addressing_RoundTrip` 对 MelsecMcServer
  实测 round-trip, 人工核对解析进制后把结论(进制+换算公式)回填本条。
  解析实现必须收敛到单一入口(如 `McAddress.Parse`), 禁止散落各处。

## 3. 批量调度语义(核心算法)
输入: 对象全部点位 → 输出: MC 请求计划

1. 按 `(区域, 字/位)` 分组 —— 字元件与位元件不得混入同一请求
2. 组内按地址升序, 合并连续段(满足 `前段.End == 后段.Addr`)
3. 每段按协议单批上限拆包: 字 ≤960 字/请求; 位 ≤7168 点/请求
   (来源: MC 协议手册; ⚠️ 动手前按实际机型手册核对, 确认后回填本条)
4. v1 请求串行执行, 结果按映射写回属性

## 4. 验收性质(必须恒成立 —— property 测试据此编写)

- **P1 覆盖性**: 所有请求覆盖的地址单元并集 == 输入点位集合(不丢、不多)
- **P2 无重叠**: 任意两请求覆盖的地址单元不相交
- **P3 合规性**: 单批大小 ≤ 协议上限
- **P4 最简性**: 请求数 == 分组 + 合并 + 拆包后的理论最小值
  (相邻段必须已合并; 超上限段必须已拆包)

## 5. 验收标准(v1.0, 读)

| 编号 | 标准 | 验证方式 |
|---|---|---|
| A1 | 7 点位对象(含 2 个连续 D 点) → 请求数 ≤ 6 | Conformance 实测往返数 |
| A2 | 200 轮随机点位(0~300 个/轮) → P1-P3 全过 | SchedulingProperties |
| A3 | X/Y 寻址 round-trip 一致; 实测结论已回填 §2.3 | Conformance + 人工回填 |
| A4 | 空对象(无标注) → 0 请求, 返回 `new T()`, 不触网 | 单元测试(无效端口) |
| A5 | 对 MelsecMcServer: 写入已知值 → 批量读回逐字段相等 | Conformance |
| A6 | 100 点位整对象读, 对本地 McServer < 50ms(预算可调) | Conformance 计时 |
| A7 | 非法地址/类型区域错配 → 扫描阶段抛 ArgumentException | 单元测试 |

## 6. 非目标(v1 明确不做)
订阅/轮询调度; 请求并发; 多 PLC 路由; 重试与断线恢复

## 7. 边界条件(读场景)
- 无任何标注属性的对象 → 0 请求, 返回 `new T()`(空实例), 不抛异常
- 两个属性标注同一地址 → **读场景允许**, 各自独立读回(不保证一致性, v1 不优化);
  写场景见 §8.4, 不允许
- 非法地址(空串/未知区域/负数/格式错) → 抛 ArgumentException
- 类型与区域不匹配(如 bool 标在 D 区) → 抛 ArgumentException

## 8. 批量写(新增于 v1.1)

### 8.1 契约与语义(实现必须遵守):
    void Write<T>(MelsecMcNet client, T instance) where T : new()
语义: 按 §8.2 生成写计划后串行执行。**Write 内部不做读回验证**,
      正确性由 A8 的测试从外部验证。

### 8.2 与读的语义对齐
- 分组、合并、拆包规则与 §3 完全一致(复用调度器, 禁止写第二份逻辑)
- 写上限与读一致: 字 ≤960/请求, 位 ≤7168/请求(⚠️ 同 §3 第 3 条, 一并核对)
- 位写入: bool → 位元件, 按 16 点打包成字写入, b0 = 最低地址

### 8.3 验收标准(新增)
| 编号 | 标准 | 验证方式 |
|---|---|---|
| A8 | 混合类型对象写 → 立即读回, 逐字段相等(写读 round-trip) | Conformance |
| A9 | P1-P4 性质对写计划同样成立(同一调度器, 独立 oracle) | WriteSchedulingProperties(新建文件) |
| A10 | 空对象写 → 0 请求, 不抛异常, 不触网(指向无效端口可调用) | 单元测试 |
| A11 | 写场景地址冲突(同一地址、规范化后相同、或地址单元重叠) → 扫描阶段抛 ArgumentException | 单元测试 |

> A9 说明: `SchedulingProperties` 是 v1.0 冻结文件, 不得修改。写计划的 P1-P4 在新建的
> `WriteSchedulingProperties` 中验证: 复用同一个调度器(如 `McBatchPlanner` 的分区实现),
> 但使用独立 oracle 与"无地址冲突"的随机输入(写场景禁止重复/重叠, 见 §8.4)。
> 为保证 A9/A11 能在无网络下断言计划, 实现应提供一个不触网的写计划入口,
> 如 `McBatchPlanner.PlanForWrite(object)`; 该入口必须与 `Write` 使用同一调度器。

### 8.4 写入特有边界(新增于 v1.1)

- 写场景下, 任意两个被标注属性覆盖的地址单元集合不得相交; 相交即在扫描阶段抛
  ArgumentException。包括三种情形:
  a) 两个属性标注同一地址(如 D100 与 D100);
  b) 多字点位的单元重叠(如 int 标 D100 覆盖 D100-D101, 同时 short 标 D101);
  c) 地址规范化后相同(如 D100 与 D0100 视为同一地址)。
  判重以 `McAddress.Parse` 解析后的 (区域, 单元编号) 为准, 不以原始字符串为准。
  理由: 读的重复只是浪费带宽, 写的重复是静默覆盖, 属危险行为, 必须显式失败。
  此条与 §7 的"读场景允许重复"并存, 按操作类型区分。
